# CLAUDE.md

This file is the project guide for Claude Code sessions in **edgex-foundry-mcp**. It is a
Model Context Protocol (MCP) server, written in Go with the official MCP Go SDK, that lets
AI agents inspect and (optionally) operate an **EdgeX Foundry (LF Edge)** deployment
through its public REST API v3. User-facing docs are in [README.md](README.md). This file
covers how to work on the code.

## Layout

```
cmd/edgex-foundry-mcp/   main: flags/env, transport (stdio | streamable HTTP), wiring
internal/config/         configuration model, loading, validation
internal/edgex/          typed HTTP client for core-metadata, core-data, core-command
internal/tools/          MCP tool + resource handlers (read tools, gated write tools)
openspec/                specs (source of truth) and changes (proposals in flight)
dev/                     docker-compose stack: upstream EdgeX (non-secure) + device-virtual
scripts/                 publish_guard.sh, small helper clients for live checks
.claude/                 skills, agents and settings used by this repo
```

## Commands

| Task | Command |
|------|---------|
| Build | `make build` (binary in `bin/`) |
| Unit tests (no live EdgeX needed) | `make test` |
| Lint (gofmt, go vet, golangci-lint) | `make lint` |
| Run over stdio against the dev stack | `make run` |
| Dev stack up / down | `make dev-up` / `make dev-down` |
| Spec validation | `openspec validate --all --strict` |
| Confidentiality scan | `scripts/publish_guard.sh` |

## Golden rules

1. **`git pull` before reviewing or editing anything.**
2. **OpenSpec first.** Every feature or fix starts as a change in `openspec/changes/`.
   Implementation follows that change's `tasks.md`, and you tick tasks off as they are done.
   No production code is written outside a change.
3. **Verify EdgeX endpoints against official sources before coding.** Use the
   `edgex-api-scout` agent. Never guess paths, query params or payload shapes. Record what
   you verified, with its source URL, in the change's `design.md`.
4. **The safety model is non-negotiable.** Read-only by default. Write or actuation tools
   are registered only with `--enable-writes`, and their descriptions must say they can
   affect physical hardware. Tokens and credential-like protocol properties are never
   logged, and they are redacted from tool output.
5. **Done means tested.** A change is not done until `make test lint` passes. When
   possible, also check it against a live EdgeX with the `edgex-live-check` skill. Confirm
   the running build through `/api/v3/version` first, because a stale container gives false
   positives.
6. **Run the `publish-guard` skill before every push.** This is a public repo.
7. **English only.** Use conventional commits. Never add `Co-Authored-By` trailers.

## Skills (`.claude/skills/`)

- `add-mcp-tool`: end-to-end recipe for one new MCP tool, from spec to client, handler,
  test, README and tasks.
- `edgex-live-check`: validates behavior against a running EdgeX (default: `dev/` stack).
  Read-only unless asked otherwise.
- `scout-feature`: runs the two scout agents in parallel before a proposal, then hands off
  to OpenSpec.
- `publish-guard`: pre-push secret and confidentiality scan. It reports findings and never
  auto-fixes.
- `release`: how versions, changelog and goreleaser work (not wired up yet).
- `openspec-*` and `/opsx:*`: generated by OpenSpec for the change workflow (new, ff,
  apply, verify, archive).

## Agents (`.claude/agents/`, all read-only)

- `edgex-api-scout`: returns the exact EdgeX REST contract for a need, with source URLs.
- `mcp-sdk-scout`: returns exact MCP Go SDK types and signatures for the version pinned in
  `go.mod`.
- `safety-reviewer`: reviews a diff against the safety model and ranks findings by
  severity.

## Local-only files (gitignored)

`.claude/settings.local.json`, `CLAUDE.local.md`, and `.claude/publish-guard.local.txt`
(a private deny-list for publish-guard, one term per line).
